# 统一交互设计规范

## 2026-10-23 最新确认：手机竖屏优先

以手机竖屏触控为首发设计与验收基准（390×844，覆盖360×640、430×932），桌面兼容。横屏仅作兼容检查，不再作为主设计方向或首发P0门槛。下文历史横屏布局、双列示意及横屏任务要求均以本条为准。

菜单遵循手机操作：内容纵向滚动，每页一个明确主动作，主要继续/出发/重试位于内容下方的拇指可达区域；长页使用不遮挡内容的底部操作区，保留系统底部安全距离。返回固定在左上且逐层返回，危险动作与继续分开，广告作为次级可选操作。目标至少48×48 CSS像素，不依赖悬停、精细点按或横向拖动。现有飞行HUD、双指按钮与飞行镜头保持；不能把菜单尺寸规范套用成HUD改版。


## 2026-10-23 用户评审更新：保留当前飞行 HUD

用户明确认可现有飞行HUD。后续保留dev.25的遥测项目、信息层级、位置、视觉样式、操作按钮及提示方式，不实施本轮提出的HUD重排、精简或新布局。默认不调整飞行镜头。菜单、选关、远征、暂停、结算与设置继续按方案评审。

横屏适配和四边安全区仍须验证，但不能以此擅自替换已认可的HUD；若实测发现必须调整HUD或镜头才能适配的冲突，单独呈现问题和最小改动方案。触控释放、模态输入隔离、传感器异常及返回路径可以继续审查；具体实现仍在后续阶段。


本项目设计目标，不冒充平台强制规范。适配现有原生DOM与Phaser；无大型UI依赖。

## 视觉与组件

|项目|规范|
|---|---|
|色彩|保留深海军蓝/星空、薄荷绿主动作、琥珀提示、珊瑚危险；危险/锁定同时使用文字或图标，不只变颜色|
|文字|正文14–16 CSS px，辅助12–14，标题22–28，关键遥测22–28；菜单文字可放大至125%而不截断；装饰英文可小但不得承载必要信息|
|层级|每页一个主动作；次动作描边，返回文字/箭头，危险动作明确名称；广告不伪装成默认继续|
|目标尺寸|常规点击目标至少48×48 CSS px；飞行转向约72–88方形、推进约96–112，间距至少8–12；以真机拇指验证调整，不按视觉图标大小设触控区|
|安全区|四边max(基本间距,系统safe-area)；旋转/窗口变化重算。不把安全区padding塞进不足的固定高度|
|布局|菜单用Grid/Flex；场景控件允许锚定定位，禁止大量相互独立的top/bottom魔数。底部动作固定，内容独立滚动；超短屏必要时整页滚动但不丢返回|
|对比度|正常正文目标至少4.5:1，大字和关键控件边界至少3:1；在实际星空/吸积盘背景上测，而非只测纯色背景|
|按钮状态|默认/按下/焦点/禁用/请求中/完成；文字说明禁用原因。网络操作单次锁；焦点不能仅靠hover|
|反馈|按下反馈目标100ms内；普通过渡120–180ms。失败立即停止操作输入，先保存再播可跳过演出。减少动态效果时去抖动/闪光，保留状态文字|
|主题|飞行场景是主角，航线与轨道线作轻量分组，避免把全屏做成表格和统计卡墙；真实榜单用紧凑列是例外|

复用 primary-button、secondary-button、text-button、starTaskMarkup、result-card 的基础样式与现有图标；新增 ScreenHeader、ActionBar、StatusMessage、ConfirmDialog、ModeBadge 等小型DOM工厂。CSS变量统一间距/字号/颜色，不整套替换引擎UI。

## 输入归属

- 顶层页面/弹窗独占菜单输入；隐藏层不可聚焦、不可点击，必要时inert。
- 飞行操控绑定触点ID；左右转与喷射独立，松开一个指头只释放其控制。pointercancel、失去捕获、暂停、权限弹窗、切后台必须清空触点。
- 仅飞行控制/按住喷射世界区使用touch-action:none；菜单内容允许纵向滚动。拖动超过阈值后取消按钮点击，不把滚动当消费。
- 切换到倾斜模式需要既有授权；在暂停状态完成校准。传感器断流暂停并提供按钮回退，恢复后要求新的按下动作；不自动点火。
- 转屏先暂停与清输入，重算四边安全区；倾斜中立姿态需明确重校准。恢复飞行必须主动操作。
- 键盘Tab/Shift+Tab访问控件，Enter/Space激活，Esc退一层或暂停；输入框里不触发R重开/M静音。远征禁止R重试。
- 不承诺本次首发支持游戏手柄；Skill的焦点原则用于键盘。若后续增加手柄，需独立映射和验收，不能因装了Skill就宣称兼容。

## 页面与返回契约

ScreenStack的每个元素保存：页面类型、模式、来源、焦点、滚动位置。业务状态继续归GameEconomy/Flight/每日服务所有。

- push只改变可见层/输入拥有者；pop不自动发金币、不结算、不重置飞船。
- 业务离开由一个统一守卫决定：远征ready/station保存退出，flight请求结束确认，failed/ended不可恢复。切菜单不能绕过守卫。
- 暂停、设置、确认叠放时，世界只冻结一次；返回设置调用处后仍暂停。恢复按一次明确的“继续”。
- 关闭危险确认默认不执行，取消回来源。浏览器/宿主不可拦截的退出由现有持久化处理。
- 文案一致：重试本关/重试保存/重试提交不可混用；已入账/已提交/仅本机记录必须来自实际回执。

## 异步结果与错误

|情形|呈现与操作|
|---|---|
|广告加载|原页保留，当前请求loading；不能通过其他按钮发起第二次同类请求；平台不支持关闭时不伪造关闭按钮|
|广告取消/失败|未发奖/未扣款，回原操作页并保留免费继续路径；请求已完成但保存失败则明确“保存未确认”，不说已奖励|
|金币消费|显示金额与结果，必要确认后单次提交；失败余额/资源均以服务实际状态为准，按钮可重试|
|排名提交|发送中/平台确认/未确认失败三态；同意后按既有每日策略自动，远征仍自愿提交；不提交模拟示例数据|
|排名读取|加载/空榜/错误区分，失败可刷新；切标签的旧回调不能覆盖新榜|
|保存失败|持久内联提醒+重试保存，不能藏进3秒toast；禁止将失败记录显示为已保存|
|传感器失效|暂停，说明原因，按钮操作回退或重新授权；不让飞船一边坠落一边要求看长说明|
|长名字/大数值|昵称截断可展开，数据列不挤压；时间mm:ss.cc，超过小时用h:mm:ss.cc；展示“完成3/30”，不显示2亿编码作核心指标|

## HUD与状态管理边界

物理保持原固定步长。UI适配层监听阶段/奖励/腿损伤/资格等低频变化；速度高度等连续数据最多10Hz取样并比较后更新，数字宽度固定，避免布局抖动。保留现有10Hz节奏作为初始上限，不为遵循事件理念把物理逐步采样改写。

每一个页面只能发业务命令或读取展示模型，不能直接修改coins、completed、stars、best。既有交易、广告防重、排行榜编码和资格校验继续在原服务里执行；首版甚至可先保留main业务函数，仅把DOM构造和导航移出。
