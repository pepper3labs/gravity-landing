# 开发日志：引力盲航是怎样一步步做出来的

## 1. 原型：先把"手感"钉死（v0.4）

最初的目标不是内容量，而是一个能被验证的飞行模型：120 Hz 固定时间步、推力与旋转分离、惯性可见，以及"两条腿分别断"的着陆判定。这一阶段确立了后来所有关卡都遵守的物理基线：任何参数改动都必须用输入驱动回放逐项对齐，而不是"感觉差不多"。

工程上同时定下了两条铁律：一是**关卡配置与物理代码分离**（`src/levels.ts` 只描述世界，`src/physics.ts` 只负责求解），二是**所有成绩只存在浏览器本地**。参数与稳定标签见 [v0.4 基线](V04-BASELINE.md) 与 [v0.4 复盘](V04-REVIEW.md)。

## 2. 训练关与航线重排（v0.5.1 / v0.5.2）

试玩反馈很直接：新手第一分钟就挫败，因为第一关就是长途航线。于是新增"起飞训练""减速训练"两关，把原先六条长航线顺延为第 3–8 关，同时保持原有关卡配置与物理不变。旧存档按版本化目录迁移，玩家进度不丢。

这一阶段开始使用"路线结果文件"作为回归证据：8 条输入驱动航线全部通关，48 项测试通过。见 [航线调整](V051-FAR-SIDE.md) 与 [训练关交付](V052-TRAINING.md)。

## 3. 星际环境：内容规模化（v0.6）

从 8 关扩到 14 关，加入高重力起降、静态小行星、动态小行星、双星障碍、低燃料精准着陆和综合挑战。关键技术决策：

- 小行星是**真实碰撞体**，轨迹确定可见，擦碰改变线速度与姿态；
- 动态障碍物使用解析轨迹与连续碰撞检测，保证回放确定性；
- 综合关在低空引入随高度衰减的大气阻力，不改变原有推力与旋转参数。

验收方式升级为"十四关固定时间步输入驱动通关 + 确定性回放 + 旧八关逐项对齐基线"，74 项测试。详见 [v0.6 交付记录](V06-DELIVERY.md) 与 [工程收尾](V06-CLOSEOUT.md)。

## 4. 重玩与结构：目标系统（v0.7）

v0.7 先补"为什么再飞一遍"：重玩目标筛选、推荐下一目标，并把独立成绩与救援成绩彻底分开存储，避免辅助通关污染排行榜数据。内容上依次扩到 15 关（第三章）、20 关（第四至五章），测试 107 → 111 项。详见 [v0.7 开发记录](V07-DEVELOPMENT.md)、[第十五关](V07-LEVEL15.md)、[关卡扩充](V07-EXPANSION.md)。

## 5. 每日挑战（v0.8）

每日挑战是第一个"时间驱动"的系统：航线由日期派生，UTC 午夜切换，与战役成绩隔离，且允许离线完整回放。为了让作弊与争议可复核，导出文件可以离线重算并校验。见 [每日挑战设计](V08-DAILY.md) 与 [收尾说明](V08-CLOSEOUT.md)。

## 6. 工程收尾与试玩（v0.9）

这一阶段几乎没有加内容，全部用于"可交付"：试玩诊断记录（最近 200 次尝试、导出 JSON）、基础设置、性能摘要、广告取消/失败的回调保护和过期回调隔离。测试从 201 增至 207 项。见 [试玩诊断](PLAYTEST-DIAGNOSTICS.md)、[设置](SETTINGS.md)、[广告恢复验证](REWARDED-AD-RECOVERY.md)。

## 7. 十关扩展与视觉升级（v0.10–v0.16）

v0.10 完成 21–25 关与"最终章"（含天体观测台关卡）；随后 v0.14 加入动态黑洞渲染管线（离屏渲染 + 着色器），v0.16 加入三星任务系统。详见 [最终章](V10-FINAL-CHAPTER.md)、[第21关](V10-LEVEL21.md) 至 [第25关](V10-LEVEL25.md)、[观测台](V10-OBSERVATORY.md)、[动态黑洞](V14-DYNAMIC-BLACK-HOLE.md)、[星级任务](V16-STAR-TASKS.md)。

## 8. 平台联调与移除（v0.17–v0.18）

曾在私有分支中接入某 H5 平台的激励广告与排行榜，并完成联调自测（见 [平台自测](V18-PLATFORM-SELFTEST.md)）。开源发布时出于版权与隐私考虑，**平台专属实现已被整体移除**：广告与榜单只保留平台无关的抽象接口（`RewardedPort` / `OnlineLeaderboardHost`），默认接 no-op 实现，成绩仅存本机。接入方式见 [从零搭建](BUILD-YOUR-OWN.md)。

## 9. 金币经济与连续远征（v0.26–v0.28）

上线前的最后一块内容：30 关主线金币解锁、星级差额奖励、跨 30 关资源继承的连续远征，以及纯净/综合双榜的客户端模型。测试达到 255 项，全部历史回放与两套构建审计通过。见 [远征计划](expedition/PLAN.md)、[资源参数](expedition/BALANCE.md)、[游戏内榜单](V26-IN-GAME-RANKINGS.md)、[排行参与与授权](V27-RANKING-CONSENT.md)、[发布前修正](V28-PRELAUNCH-FIXES.md)。

## 10. 1.0 候选（rc.1–rc.3）

收尾阶段只做减法和验收：教程与结算一屏化、手机布局修正、发布候选包复核清单。当前 244 项测试、30/30 回放档案重放通过、两套构建审计通过。见 [候选检查清单](RELEASE_CHECKLIST.md) 与 [rc.1 就绪度](V1-RC1-READINESS.md)。

## 工程方法：为什么这个项目敢说"没改坏"

1. **确定性物理**：120 Hz 固定步进 + 输入序列回放，任何参数变动都能逐帧对比。
2. **永久回放档案**：每关的最佳路线以 `docs/replays/*.json.gz` 固化，`npm run verify:replays` 直接复现终态；改规则必须显式重录（`record:replays`）。
3. **基线冻结**：旧版本的结果文件（如 `docs/v06-route-results.json`、`docs/v07-route-results.json`）保留为对照，新测试断言旧成绩不变。
4. **证据留档**：每次批次的测试、构建与审计输出写入 `docs/evidence/`；决策记录在 [DECISIONS](DECISIONS.md)，逐次进度在 [PROGRESS](PROGRESS.md)，测试覆盖在 [TEST_MATRIX](TEST_MATRIX.md)。

如果你想在这个基础上继续开发，从 [从零搭建自己的版本](BUILD-YOUR-OWN.md) 开始。
