# 永久输入回放档案

2026-10-14：十四关完整自动驾驶输入已保存到 `docs/replays/`，压缩档案合计 1,830,861 bytes（约 1.75 MiB）。每份档案从标准停泊状态开始，使用正式推进/旋转输入，无瞬移、无救援、无损伤覆盖。它们证明存在可复现通关路线，不证明真人难度或实体手机性能。

## 使用

```sh
npm run verify:replays
```

该命令只读取清单和已有档案，逐步调用正式 `Flight.step`；不会重新调用自动驾驶生成输入，不写浏览器存档，也不上传数据。清单缺失、重复、文件损坏、规则不兼容或重放结果不符时以非零状态退出。

```sh
npm run record:replays
```

仅在明确需要更新自动验证基线时运行此命令。它会先在内存中生成并验证全部十四关，再替换 `docs/replays/` 下相应档案和清单；随后再次从磁盘读取验证。修改物理或关卡规则后，不应直接重录掩盖回归，需先按 AGENTS 做基线对比和决策记录。现有历史标签与 Git 提交保留旧版本。

## 格式与校验

- 清单 `manifest.json`：稳定关卡 ID、固定文件名、压缩文件 SHA-256、大小、步数、用时、余油与航迹点数。
- 每关 `.json.gz` 解压后为 `{sha256,payload}`。SHA-256 对 JSON payload 校验，便于识别意外改动；**不是数字签名，也不是反作弊保证**。
- payload：格式版本 1、来源 automated-verification、游戏版本、记录时 HEAD、Node/系统/架构、关卡 ID 与配置指纹、规则指纹、航线版本、固定步 1/120 秒、初态 docked、seed=null、步数、输入及预期终态。
- 当前关卡无随机生成，因此 seed 明确为 null。记录时 HEAD 是生成工作区的起点参考；兼容性由实际文件和关卡指纹验证，不能把 HEAD 自动视为所有未提交文件的快照。
- 规则指纹覆盖 physics、environment、level-types、scoring 四份源文件，先统一 CRLF/LF；关卡指纹覆盖当前完整配置。无关 UI 修改或仅自动驾驶策略调整不会改变物理规则指纹。
- 输入为无损 RLE 三元组 `[重复步数, 推进0或1, 转向]`，转向保留完整双精度，负零用 `"-0"` 表示。外层 gzip 压缩，无坐标插值、数值舍入或有损采样。
- 比较位置、速度、角度、角速度、时间、燃料、支架状态、冲击、接触、补救标记、触地指标、完整评分，以及完整采样航迹的 SHA-256 和点数。终局之后不允许填充多余指令。
- 压缩输入和解压结果均限制 8 MiB；动作展开限制 57,600 步（480 秒），先验证段格式、转向范围、整数次数及总步数，再模拟。
- 不兼容或损坏档案被明确拒绝，不自动迁移、不静默重新生成。跨 Node/JS 数学实现的逐位一致性未获保证；运行时信息用于排查，结果不相等时不会放宽标准冒充通过。
